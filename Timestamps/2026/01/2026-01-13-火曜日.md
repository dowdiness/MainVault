## 📅 質問

### 🚀 今日やること

[starlight](https://github.com/withastro/starlight) のヘッダーが日本語で正しく動作しない問題を修正する

ご提示いただいた画像を見ると、日本語版のヘッダーでナビゲーションリンク（「ドキュメント」など）が**縦書きのように重なって崩れている**非常に特徴的な挙動が確認できます。

これはStarlightの `Header.astro` が持つ**CSS Gridの計算ロジック**と、**日本語（CJK）特有の折り返しルール**が衝突することで発生する現象です。

### 1. 最小幅の計算ミス (`min-content` の挙動)

Starlightのヘッダーは、タイトルエリアに対して以下のような計算を行っています。

> `minmax(calc(var(--__sidebar-width) + ...), auto)`

- **ラテン文字 (英語):** 英語の単語（"Enterprise" など）は途中で改行されにくいため、ブラウザは「単語の長さ」を最小幅として認識します。
    
- **日本語:** 日本語は「どこでも改行できる」という特性（禁則事項を除く）があります。ブラウザが「幅が足りない」と判断すると、1文字ごとに折り返してしまい、画像のように**1文字ずつ縦に並ぶ**状態になります。
    

### 2. コンテンツ溢れの処理 (`overflow: clip`)

`Header.astro` には以下のスタイルが定義されています。

CSS

```
.title-wrapper {
  overflow: clip; /* 長すぎるタイトルが検索ボタンを覆うのを防ぐ */
  min-width: 0;
}
```

- **原因:** 日本語版では、翻訳によってテキストが長くなる、あるいは全角文字で幅を取ることがあります。このとき、ブラウザが「コンテナ幅を縮小しても良い」と解釈すると、日本語のテキストは「折り返し可能」とみなされ、横幅を極限まで削って縦に伸びようとします。
    

### 3. 言語による「単語」の認識差

英語の "Docs" は1つの塊ですが、日本語の "ドキュメント" はブラウザから見ると「5つの改行可能なポイント」がある塊に見えます。ヘッダーのGridレイアウトが検索バー（`1fr`）にスペースを譲ろうとした結果、ナビゲーションリンクの幅が圧縮され、日本語だけが縦に崩れてしまっています。

---

### 修正方法

この挙動を修正するには、StarlightのカスタムCSS（`custom.css`）に以下のコードを追加して、テキストの折り返しを禁止するのが最も効果的です。

CSS

```
/* ヘッダーのナビゲーションリンクが縦に崩れるのを防ぐ */
.title-wrapper a, 
.right-group a,
.sl-flex.print\:hidden a {
  white-space: nowrap;
}
```

これにより、ブラウザに対して「日本語であっても勝手に改行（縦並び）せず、1行として扱いなさい」と強制でき、英語版と同じようなレイアウトを保つことができます。
