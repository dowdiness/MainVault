# 第1章 集合と関数を読み解く

> この章では、TaPL の本文に頻出する **集合の表記** と **写像（関数）の表記** を、プログラマーが馴染んでいる「型」と「関数のシグネチャ」と対応させながら読めるようにします。

## 1.1 なぜここでつまずくのか

> ⚠️ **以下は叩き台です。**石本さんの実体験で書き直してください — ページ番号、つまずいた具体的な記号、誰にどう聞いたかなどを差し替えると説得力が劇的に上がります。

TaPL を最初に手に取ったとき、私は仕事で TypeScript の型を毎日書いているフロントエンドエンジニアでした。型のことなら少しは分かっているつもりでした。

第1章を開いた瞬間、その自信は粉々になりました。

「メタ言語」「対象言語」という言葉が並び、横棒で区切られた式が現れ、`Γ ⊢ t : T` のような記号が説明なく使われている。日本語の単語は読めるのに、文として何を主張しているのかが分からない。Twitter で勧められて買った本のはずなのに、自分には早すぎたのかもしれない、と思いました。

特にきつかったのは、推論規則の横棒の意味と、集合の表記の `{ x | P(x) }` の縦棒、関数の `f : A → B` の矢印が、どれも同じくらいの頻度で出てきて、しかもそれぞれが「説明されないもの」として扱われていたことです。本文は「読者がこの表記法を既に知っている」前提で進みます。実際の数学科の学生はそれを学部1年で習います。でも、独学のプログラマーには、その前提自体が成立していない。

何度か挑戦して、何度か挫折して、結局やったのは「TaPL 以外の本で表記法だけ先に習う」という遠回りでした。数理論理学の入門書を1冊、集合論の入門書を1冊、それを読んでから TaPL に戻ると、嘘のようにスラスラ読めるようになりました。

つまり、TaPL は内容が難しいのではなく、**前提知識の壁** が高いのです。そしてその壁は、適切な順序で薄い説明を与えられれば、数十ページで越えられる程度のものでしかありません。

この本はその数十ページを提供します。同じ穴に落ちている人が、同じ遠回りをしなくて済むように。

## 1.2 集合の3つの書き方

TaPL に出てくる集合の表記法は、実は3パターンしかありません。

### パターンA: 外延的記法（要素を並べる）

```
S = {0, 1, 2}
```

**読み方**: 「S は 0、1、2 という3つの要素からなる集合」

プログラマー的に読むなら、TypeScript の以下と対応します。

```typescript
type S = 0 | 1 | 2;
```

集合の要素 = リテラル型のユニオン、と読み替えれば違和感が消えます。

### パターンB: 内包的記法（条件で記述する）

```
S = { x ∈ ℕ | x < 3 }
```

**読み方**: 「自然数 x のうち、x < 3 を満たすものすべての集合」

縦棒 `|` は「ただし」「のうち」と読みます。プログラマーには filter のように見えるはずです。

```typescript
// 擬似的な対応
const S = naturalNumbers.filter(x => x < 3);
```

### パターンC: 帰納的定義（規則で生成する）

```
0 ∈ S
n ∈ S ならば n + 1 ∈ S
```

**読み方**: 「0 は S の要素である。n が S の要素なら n + 1 も S の要素である」

これが TaPL でラムダ項の集合などを定義するときの主な書き方です。プログラマー的には **再帰的なデータ型の定義** と同じです。

```typescript
type S =
  | { kind: "zero" }
  | { kind: "succ"; prev: S };
```

> ⚠️ 以下は叩き台です。TaPL の **実際のページ番号と式** を引用して差し替えると一気に説得力が出ます。

### 集合の表記を見分けるフロー

中括弧 `{ ... }` が出てきたら、その中身を **次の順番で確認** します。

1. **カンマ区切りで具体的な要素が並んでいるか？** → パターンA（外延的）
   - 例: `{ true, false }`、`{ 0, 1, 2 }`

2. **縦棒 `|` があって、前に変数、後に条件か？** → パターンB（内包的）
   - 例: `{ x ∈ ℕ | x が偶数 }`
   - 縦棒は「:」で書かれることもあります（`{ x : x ∈ ℕ, x < 5 }`）

3. **中括弧の **外** に「○ ∈ S」のような式が縦に並んでいるか？** → パターンC（帰納的）
   - 例: TaPL 第3章でラムダ項の集合を定義している部分（読み始めて見つけたページ番号をここに記入）

判別を間違えると意味が全く逆になるので、最初のうちは紙に書き出して確認することをおすすめします。

慣れてくると、パターンCが圧倒的に多いことに気づきます。TaPL のラムダ項、型、評価規則の集合はすべてパターンCで定義されているからです。「規則で生成する集合 = 再帰的データ型」という対応を頭に叩き込んでおくと、後の章が楽になります。

## 1.3 写像（関数）の表記

集合の次に多いのが写像（map）の表記です。

### 基本形

```
f : A → B
```

**読み方**: 「f は A から B への写像（関数）」

TypeScript の型注釈と全く同じ意味です。

```typescript
const f: (a: A) => B;
```

矢印 `→` を `=>` と読み替えれば、ほとんどの混乱は消えます。

### 写像の値を指定する書き方

```
f(x) = x + 1
```

これは普通の関数定義。

```typescript
const f = (x: number) => x + 1;
```

### TaPL でよく出る難しい形

```
f : { 1, 2, 3 } → { a, b }
f(1) = a
f(2) = a
f(3) = b
```

**読み方**: 「f は集合 {1,2,3} から集合 {a,b} への写像で、具体的にはこう振る舞う」

ここで重要な点：**写像は無限の関数ではなくテーブル（対応表）として読める**ことが多い、ということ。TaPL の文脈関数 Γ や置換 σ も、ほとんどは小さなテーブルに過ぎません。

> ⚠️ 以下は叩き台です。TaPL の **第3章あたりの実際の型付け規則** から1例を選んで、Γ の中身を具体的に並べる例に差し替えてください。

### 例: 型付け文脈 Γ

TaPL の型付け規則に登場する `Γ ⊢ t : T` の `Γ`（ガンマ、文脈）も、結局は小さなテーブルです。

たとえば `Γ = x : Bool, y : Nat → Nat` という文脈は、次のテーブルに過ぎません。

| 変数 | 型 |
|---|---|
| x | Bool |
| y | Nat → Nat |

つまり Γ は「変数名 → 型」という写像です。TaPL では `Γ(x) = Bool` のような書き方も出てきますが、これはこのテーブルから `x` の行を引いてくる、それだけのことです。

`Γ, x : T` という記法も同様に、テーブルに新しい行 `(x, T)` を追加するだけ。

```typescript
// 擬似コード
type Context = Map<string, Type>;
const newContext = new Map(oldContext).set("x", T);
```

この対応が頭に入っていれば、3章以降で頻出する `Γ ⊢ t : T` という記法を見たときに、「テーブル Γ のもとで、項 t は型 T を持つと判定できる」と素直に読めるようになります。

## 1.4 まとめ

この章で身につけたこと：

- 集合の3つの書き方（外延的・内包的・帰納的）と、それぞれが TypeScript の何に対応するか
- 写像 `f : A → B` は単なる関数の型シグネチャ
- 写像はしばしばテーブルとして読み替えられる
